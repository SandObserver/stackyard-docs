Stackyard is one image for `linux/amd64` and `linux/arm64`. On Unraid, use the [Unraid template](/docs/installation/unraid/).

## Compose

```yaml
services:
  stackyard:
    image: ghcr.io/sandobserver/stackyard:latest
    container_name: stackyard
    restart: unless-stopped
    ports:
      - "8700:80"
    volumes:
      - data:/data
      - icons:/icons

volumes:
  data:
  icons:
```

```sh
docker compose up -d
```

Open `http://<host>:8700`.

`/data` holds the config file. `/icons` holds uploaded icons and wallpapers. The container runs as the image's `node` account, UID 1000. A named volume belongs to that account from creation. A bind mount such as `./data:/data` must be writable by UID 1000 before the first start:

```sh
mkdir -p data icons && sudo chown -R 1000:1000 data icons
```

Earlier versions of the Compose file used `./data` and `./icons`. Keep those lines if yours has them; the data stays where it is.

The [compose file in the repository](https://github.com/SandObserver/stackyard/blob/main/docker-compose.yml) adds hardening and lists every variable below.

## docker run

```sh
docker run -d --name stackyard --restart unless-stopped \
  -p 8700:80 -v stackyard_data:/data -v stackyard_icons:/icons \
  ghcr.io/sandobserver/stackyard:latest
```

## Running as another account

Set `user: "<uid>:<gid>"` in Compose, or `--user <uid>:<gid>` with `docker run`. The two volumes must be writable by that account. No capability is needed.

A system that reserves ports below 1024 for root, such as host networking, refuses port 80 for other accounts. Set `LISTEN_PORT` to a higher port and map that port instead. The container says so and stops when it cannot bind.

For a read-only root filesystem, set `read_only: true` and mount a tmpfs on `/run/stackyard`.

To run as root, set `user: "0:0"` and add `NET_BIND_SERVICE`, `CHOWN`, `SETUID`, `SETGID`, `DAC_OVERRIDE` and `KILL` under `cap_add`. The container then takes ownership of the two volumes at start, and runs the API as `node` and the nginx workers as `nginx`.
